## Executive summary

**Overall 3/10. Production readiness 1/10.** The repository contains a sizeable shopping prototype and a buildable browser bundle. The clean checkout cannot load the backend because the entire ORM model package is missing. That also blocks migrations, commerce workflows, and live agent and voice verification. The platform has several independent release blockers visible in source, including cross-user chat and order data access, unrestricted seller elevation, client-controlled tool approval, invalid quantities reaching checkout, and development startup routines that can delete graph and SQL data.

Recover the missing source and a reproducible Linux baseline first. Before connecting real users or data, close the authentication, ownership, tool approval, upload and log exposure gaps. Then unify commerce rules, make search and voice reliable under failures, and qualify the deployment with migration, browser, performance and recovery tests.

## Scope and interpretation

The backup snapshot has 131 tracked files. The review covers the tracked backend, frontend, tests, deployment, manifests and locks, scripts and three READMEs. The supplied project rules governed the audit. No tracked `AGENTS.md`, CI workflow or license file exists in this snapshot. Baseline commands ran in a disposable Git archive. The report uses **Confirmed** for results established by source or an executed check, **Risk** for effects dependent on runtime, topology or data, **Gap** for absent capabilities, and **Improvement** for optional work. Severity reflects deployment impact. Static security findings describe code paths and controls. Live security attack reproduction was outside this audit. A finite review cannot establish that every latent defect has been found.

**Request lifecycle.** In development Vite forwards `/api` to Uvicorn. In production nginx forwards `/api/` to Granian. REST dependencies resolve the JWT subject to the DB user, and protected endpoints apply role and object filters where implemented. Commerce reads and writes Postgres and product APIs use Redis cache. Text turns create or accept a session ID, stream SSE, and try pending-state resumption, local command handling, then LLM classification and a Python tool. Voice turns use microphone PCM, server VAD and ASR, then the same streaming orchestrator and Piper playback. Search merges Qdrant and SQL candidates, then fetches authoritative product rows. Neo4j stores layout metadata on the side. PostgreSQL is the intended source of truth. Redis, vector and graph updates occur separately from SQL commits. No independent worker queue or durable event propagation exists.

## Security and production readiness

Security controls that are present include parameterized SQLAlchemy and Cypher query values in reviewed paths, JWT signature verification with a configured algorithm, HttpOnly main session cookies, owner filters for many customer writes and seller products, and rating validation for delivered owned orders. No live security reproduction was run. Dependency scanner results do not replace object-level tests or prove a production image is clean.

Production release should require private data services and real secret management, checked session ownership and capability policy, safe uploads and error logging, unified transactions, known-dependency startup, shipped artifact and model verification, measured resource limits, observability and successful restore. Testing existing services with the default startup would risk data deletion, so verification used isolated inputs and non-destructive startup commands.

## Missing verification and release evidence

- Database and commerce need a clean migration, existing-data upgrade, model-to-DDL parity, idempotent seed, last-unit/duplicate checkout contention, no partial rollback leakage, address and ratings races and mixed-seller workflow coverage.
- Auth and agent need real API-level user isolation, cookie/logout and OAuth provisioning, denial across every dispatcher entry, confirmation expiry/concurrency, untrusted product description handling, provider deadline/fallback and factual grounding tests.
- Search needs a versioned relevance corpus with empty queries, synonyms, out-of-stock products, stale vectors and service outages. Voice needs deterministic fixtures plus real Parakeet/Piper CPU and supported GPU runs, breakpoint cancellation, slow clients, concurrent sessions, sample-rate and reconnect checks.
- Frontend needs lightweight component and contract tests plus independently seeded headless browser tests for each customer and seller journey, keyboard/a11y and mobile layouts. Existing checks do not establish browser workflow correctness.
- Deployment needs lint/build and dependency gates, model checksums, image SBOM and vulnerability scans, startup and rollback drills, latency and capacity load tests, and measured backup/restore targets.
